# Styling — the deck's color palette

Full mechanics of `/slide-creator style <name> [palette]`. The idea: a single source of truth (`palette.json`) from which the skill generates `uno.config.ts` (which injects UnoCSS tokens + CSS variables + base rules via `preflights`). The skill **never touches `style.css`** — that file is 100% user-owned.

---

## Flow

1. **Get the palette** — from [coolors.co](https://coolors.co/image-picker) (upload image → pick colors → "Export" → any Code format) or reuse another deck's.
2. **Run** `/slide-creator style <name> <palette>`.
3. The skill writes `palette.json` + regenerates `uno.config.ts`.
4. **Edit `palette.json`** if you want to change roles. Re-run `/slide-creator style <name>` (no args) to regenerate `uno.config.ts`.

---

## Separation of responsibilities

| File | Owner | What it contains |
|------|-------|------------------|
| `palette.json` | skill | Source of truth: `colors` + `roles` + `source` |
| `uno.config.ts` | skill (fully regenerated) | `theme.colors` (UnoCSS tokens) + `preflights` with `:root { --c-* }` and base rules |
| `style.css` | **user** | Everything else: workarounds, typography, custom classes. The skill never reads or writes this. |

Why: Slidev already separates these pieces. UnoCSS `preflights` lets you inject arbitrary CSS into the bundle, so the "generated" file is just one (`uno.config.ts`), it never collides with whatever the user has in `style.css`, and no preservation markers or migrations are needed.

---

## Accepted inputs

Parsing is robust — feed the skill any of these:

### 1. Coolors URL
```
https://coolors.co/43012a-cd3ade-fc32ac-ad096b-91234a
```
→ extracts hexes from the path. Names are generated as `c1, c2, ...`.

### 2. Coolors export — Object
```json
{"Crimson Violet":"43012A","Vivid Orchid":"CD3ADE","Brilliant Rose":"FC32AC","Medium Violet Red":"AD096B","Vintage Berry":"91234A"}
```
→ preserves readable names. **Preferred format.**

### 3. Coolors export — Extended Array
```json
[{"name":"Crimson Violet","hex":"43012A","hsl":[323,97,13],...},...]
```
→ uses HSL to auto-suggest roles (lightness → bg/fg, saturation → primary).

### 4. Loose hexes
```
#43012A #CD3ADE #FC32AC #AD096B #91234A
```
or without `#`, separated by spaces or commas.

### 5. No arguments
```
/slide-creator style <name>
```
→ reads the existing `palette.json` and regenerates `uno.config.ts`. Useful after editing `roles` by hand.

## `palette.json` — schema

Lives at the root of the deck (`<SLIDES_DIR>/<name>/palette.json`).

```json
{
  "source": "https://coolors.co/43012a-cd3ade-fc32ac-ad096b-91234a",
  "colors": {
    "Crimson Violet":     "#43012A",
    "Vivid Orchid":       "#CD3ADE",
    "Brilliant Rose":     "#FC32AC",
    "Medium Violet Red":  "#AD096B",
    "Vintage Berry":      "#91234A"
  },
  "roles": {
    "bg":         "Crimson Violet",
    "fg":         "Vivid Orchid",
    "primary":    "Brilliant Rose",
    "primary-dk": "Medium Violet Red",
    "accent":     "Vintage Berry"
  }
}
```

- **`source`** — optional, traceability. The coolors URL or whatever you pasted.
- **`colors`** — dictionary `name → #hex`. If the source didn't carry names, they are `c1, c2, ...`.
- **`roles`** — semantic mapping `role → color name`. The generator consumes this.

Edit `roles` (or change a hex in `colors`) → re-run `/slide-creator style <name>` with no args → `uno.config.ts` is updated.

---

## Roles

| Role | Expected use |
|------|--------------|
| `bg` | Slide background |
| `fg` | Body text |
| `primary` | Main accent — headlines, emphasis, CTAs |
| `primary-dk` | Darker variant of `primary` — hover, links, dividers |
| `accent` | Color touches — badges, highlights, chart accents |

---

## Automatic role mapping

When the input doesn't carry explicit roles, the skill suggests assignments and **asks for confirmation before writing**.

### Heuristic for 5 colors
Sort by HSL lightness L:

| Color (order by L) | Suggested role |
|--------------------|----------------|
| Lightest (max L) | `bg` |
| Darkest (min L) | `fg` |
| Most saturated (max S) among the rest | `primary` |
| Darker variant of `primary` (same H ±20°, lower L) | `primary-dk` |
| The leftover | `accent` |

### ≠5 colors
- **<5:** the skill explicitly asks which color maps to which role.
- **>5:** proposes the 5 most distinct ones by HSL distance, leaves the rest in `colors` without a role (available to assign manually later).

### Override
You can always edit `roles` in `palette.json` and re-run `/slide-creator style <name>` with no args.

## Generated file: `uno.config.ts`

```ts
// === GENERATED by /slide-creator style — regenerated from palette.json ===
// Do not edit by hand. Edit palette.json and re-run `/slide-creator style <name>`.
import { defineConfig } from 'unocss'

const palette = {
  bg:           '#43012A', // Crimson Violet
  fg:           '#CD3ADE', // Vivid Orchid
  primary:      '#FC32AC', // Brilliant Rose
  'primary-dk': '#AD096B', // Medium Violet Red
  accent:       '#91234A', // Vintage Berry
}

export default defineConfig({
  theme: { colors: palette },
  preflights: [{
    getCSS: () => `
      :root {
        --c-bg: ${palette.bg};
        --c-fg: ${palette.fg};
        --c-primary: ${palette.primary};
        --c-primary-dk: ${palette['primary-dk']};
        --c-accent: ${palette.accent};
      }
      .slidev-layout { background: var(--c-bg); color: var(--c-fg); }
      .slidev-layout h1,
      .slidev-layout h2 { color: var(--c-primary); }
      .slidev-layout a { color: var(--c-primary-dk); }
      .slidev-layout strong { color: var(--c-accent); }
    `,
  }],
})
```

This file is **fully regenerated** every time. Don't edit by hand — changes are lost on the next `/slide-creator style`. To extend styles, use `style.css`.

## How to use the palette in slides

Three ways, mixable:

### 1. UnoCSS tokens (preferred — more readable in `slides.md`)
```md
# <span class="text-primary">Title with accent</span>

<div class="bg-bg text-fg p-4 border-l-4 border-primary-dk">
  Styled block
</div>
```

### 2. CSS variables (for arbitrary HTML or inline styles)
```html
<div style="background: var(--c-accent); color: var(--c-bg);">
  Badge
</div>
```

### 3. Per-slide frontmatter
```md
---
class: bg-bg text-fg
---

# Slide with theme background
```

Or a one-off background override:
```md
---
class: text-fg
background: '#FC32AC'  # or use var(--c-primary) in CSS
---
```

## Per-deck customization

- **Change a color:** edit `colors` in `palette.json` → `/slide-creator style <name>` with no args.
- **Reassign a role:** edit `roles` in `palette.json` → `/slide-creator style <name>` with no args.
- **Add your own CSS rules** (typography, custom classes, workarounds): write directly in `style.css`. The skill doesn't touch it.
- **Replace the entire palette:** `/slide-creator style <name> <new-palette>` — asks for confirmation before overwriting `palette.json`.

---

## Integration with `create`

The `/slide-creator create` command **does not** generate a palette — the deck is born with the `seriph` theme defaults. The palette is added afterward via `/slide-creator style`, which lets you:

1. Create the deck quickly without deciding on colors.
2. Try different palettes (`/slide-creator style` is idempotent).
3. Reuse another deck's palette (copy its `palette.json` and run `/slide-creator style <name>` with no args).

The `style.css` that `create` copies from templates (with the Slidev 0.49.x Goto-dialog workaround) stays untouched — `style` never reads it.

---

## Notes

- **CSS vars AND UnoCSS tokens from a single source:** both come out of `palette` in `uno.config.ts`. Change `palette.json`, both consumers update.
- **Color names:** the ones from coolors are auto-generated but useful for conversation ("bump saturation on Brilliant Rose"). They have no structural role — the mapping lives in `roles`.
- **One palette per deck:** presentations are shown in a single mode. There's no dark-mode support or alternate palettes — if you need two versions, make two decks.
